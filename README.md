# UniMate

Telegram-бот для учебных дедлайнов студентов SDU: добавьте задачу с названием и дедлайном, смотрите активные задачи и задачи «на сегодня», отмечайте выполненные и получайте напоминание за час до срока.

Стек: Python 3.12+, aiogram 3.x, SQLite (aiosqlite), python-dotenv, pytest.
Продуктовые границы описаны в [`spec.md`](spec.md), правила разработки — в [`AGENT.md`](AGENT.md).

## Возможности

| Команда / кнопка | Действие |
|---|---|
| `/start` | Приветствие и главная клавиатура |
| `/help` | Краткая инструкция и формат дедлайна |
| `/add` · «Добавить задачу» | Создать задачу: название (1–200 символов), затем дедлайн `ДД.ММ.ГГГГ ЧЧ:ММ` (время `Asia/Almaty`) |
| `/tasks` · «Мои задачи» | Активные задачи по возрастанию дедлайна, по 10 на странице, кнопка «Выполнено» |
| `/today` · «На сегодня» | Активные задачи с дедлайном в текущем календарном дне (`Asia/Almaty`) |
| `/cancel` | Отменить создание задачи (ничего не сохраняется) |

Команда или кнопка меню посреди создания задачи прерывает мастер. Бот работает только в личном чате.

## Быстрый старт

```bash
# 1. Виртуальное окружение
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 2. Зависимости
pip install -r requirements.txt

# 3. Конфигурация
cp .env.example .env               # Windows: copy .env.example .env
# откройте .env и укажите BOT_TOKEN от @BotFather

# 4. Запуск
python -m app.main
```

Остановка — `Ctrl+C`: polling, фоновый worker и соединение с БД закрываются корректно.
Если `BOT_TOKEN` не задан, приложение завершится с понятной ошибкой до запуска polling.

## Конфигурация (`.env`)

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `BOT_TOKEN` | да | — | Токен бота от @BotFather |
| `DB_PATH` | нет | `data/unimate.sqlite3` | Путь к файлу SQLite (каталог создаётся автоматически) |
| `TIMEZONE` | нет | `Asia/Almaty` | Часовой пояс интерфейса и расчёта «сегодня» |
| `LOG_LEVEL` | нет | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |

Файл `.env` и базы данных исключены из git. Токен не логируется.

## Тесты

```bash
python -m pytest
```

Тесты работают без токена и без сети: используют временную SQLite БД, управляемые часы и подменённый Telegram API.

## Напоминания

- Напоминание отправляется один раз за час до дедлайна (`deadline − 1 час`) и только для активных задач с дедлайном в будущем.
- Фоновый worker проверяет БД каждые 30 секунд. Если задача создана менее чем за час до дедлайна, напоминание придёт при ближайшей проверке.
- **Напоминания работают только пока процесс бота запущен и Telegram API доступен.** Для своевременных уведомлений бот должен работать постоянно (сервер, VPS, systemd/Docker и т. п.).
- После перезапуска worker подберёт пропущенные напоминания, если дедлайн ещё не наступил. О прошедших дедлайнах напоминания не отправляются.
- Если отправка не удалась, ошибка логируется и попытка повторяется на следующем цикле до дедлайна.
- Предполагается один запущенный экземпляр бота.

## Структура проекта

```text
app/
  main.py                 точка входа, сборка Dispatcher, запуск/остановка worker
  config.py               чтение и валидация переменных окружения
  logging_setup.py        логирование с маскированием токена
  models.py               Task, TaskPage, константы (лимиты, пагинация, время напоминания)
  timeutils.py            aware-datetime, сериализация UTC, границы локального дня
  handlers/
    start.py              /start, /help, ответ в группах
    tasks.py              создание задачи (FSM), списки, «Выполнено»
  services/
    task_service.py       валидация, создание, списки, завершение
    reminder_service.py   фоновая отправка напоминаний
  repositories/
    task_repository.py    параметризованные SQL-запросы
  db/
    connection.py         соединение и идемпотентная инициализация
    schema.sql            таблица tasks и индексы
  keyboards/
    main_menu.py          главная клавиатура
    task_list.py          inline-клавиатура списка и callback-data
tests/
  unit/                   конфигурация, валидация, время
  integration/            репозиторий, сервисы, worker, Telegram-хендлеры
```

Поток запроса: `Telegram Update → Handler → Service → Repository → SQLite`.
Идентификатор владельца берётся только из `from_user.id`; каждый запрос к задачам ограничен этим ID.

## Ограничения MVP

Нет редактирования/удаления задач, свободного ввода дат, импорта из внешних систем, групповых чатов и гарантии доставки при выключенном боте.
Незавершённый диалог создания задачи хранится в памяти процесса и теряется при перезапуске.
