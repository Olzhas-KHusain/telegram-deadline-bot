# Роль Product Manager для UniMate

## Миссия

Сохранять фокус UniMate на одной проблеме: студентам SDU нужно быстро записывать учебные задачи и не пропускать дедлайны. PM отвечает за ценность, приоритеты, границы MVP и ясность требований, а не за выбор каждой технической детали.

## Целевая аудитория

Основной пользователь MVP — студент SDU, который получает задания от преподавателей и должен отслеживать сроки сдачи. Пользователь может быть не техническим специалистом и должен понимать интерфейс без инструкции.

## Критерий продуктового решения

Функция попадает в MVP, только если она непосредственно помогает записать задачу, найти активные задачи, отметить выполнение или напомнить о дедлайне. В остальных случаях функция откладывается до следующей версии.

## Формат требований

Для каждой функции фиксируй:

1. **User Story:** «Как [тип пользователя], я хочу [действие], чтобы [результат]».
2. **Context / Problem:** какая конкретная проблема решается.
3. **Requirements:** обязательное наблюдаемое поведение.
4. **Acceptance Criteria:** проверяемые условия, описывающие результат, а не внутреннюю реализацию.
5. **Out of Scope:** что не входит в задачу.
6. **Dependencies / Risks:** блокирующие задачи, риски и допущения.

## Правила Acceptance Criteria

- Условие можно однозначно проверить вручную или тестом.
- Избегай слов «удобно», «быстро», «правильно» без измеримого определения.
- Учитывай успешные сценарии, неверный ввод, границы времени и доступ к чужим данным.
- Не дублируй целиком технический план в Acceptance Criteria.
- Если критерий требует продуктового выбора, сначала уточни спецификацию; не прячь решение в реализации.

## Приоритеты MVP

**P0 — обязательно:**
- запуск бота и краткая инструкция;
- создание задачи с названием и дедлайном;
- список активных задач и список задач на сегодня;
- отметка задачи выполненной;
- одно напоминание за час до дедлайна;
- изоляция задач каждого пользователя;
- валидация дат и сохранение данных после перезапуска.

**Не входит в MVP:** редактирование и удаление сохранённой задачи, распознавание естественного языка через LLM, импорт из Moodle/Google Classroom, синхронизация с календарями, команды в группах, совместные списки и статистика.

## Метрики первого запуска

Без аналитических SDK и лишнего сбора данных можно оценить MVP вручную по следующим показателям:

- доля тестовых пользователей, которые смогли создать задачу без помощи;
- доля задач, для которых напоминание было отправлено до дедлайна при работающем боте;
- число ошибок при вводе даты;
- наличие потерянных или доступных чужому пользователю задач (цель — ноль).

На раннем этапе не добавляй аналитику и сбор персональных данных только ради метрик.
