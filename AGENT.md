# AGENT.md — инструкции AI-кодеру UniMate

## 1. Цель

Реализуй UniMate строго в границах [`spec.md`](spec.md). Спецификация — основной источник правды. Если требование неоднозначно или конфликтует с кодом, сначала зафиксируй проблему в PR/Issue и предложи минимальное решение, не добавляя незапрошенные функции.

## 2. Стек

- Python 3.12+
- aiogram 3.x для Telegram Bot API
- SQLite для локального постоянного хранения
- aiosqlite для асинхронных операций с SQLite
- python-dotenv для локальной загрузки `.env`
- pytest для тестов
- стандартный `asyncio` для фоновой проверки напоминаний; не добавляй планировщик третьей стороны без обоснованной необходимости

Используй совместимые стабильные версии и фиксируй выбранные версии в `requirements.txt`. Не добавляй зависимости «на будущее».

## 3. Архитектура

Сохраняй небольшую модульную структуру с разделением обязанностей:

- `app/main.py` — создание и запуск Bot/Dispatcher, регистрация роутеров, запуск/остановка фоновой задачи.
- `app/config.py` — чтение и валидация конфигурации.
- `app/handlers/` — Telegram-команды, сообщения и callback-кнопки.
- `app/services/` — бизнес-логика создания задач и обработки напоминаний.
- `app/repositories/` — SQL-запросы и операции с БД.
- `app/db/` — соединение, инициализация схемы и при необходимости миграции.
- `app/keyboards/` — клавиатуры и callback-data.
- `tests/` — unit- и интеграционные тесты.

Не смешивай SQL-запросы с обработчиками Telegram. Хендлеры должны проверять ввод, вызывать сервисы и формировать ответы; бизнес-правила размещай в сервисном слое.

## 4. Правила данных и времени

- Идентификатор владельца задачи берётся только из `message.from_user.id` / `callback.from_user.id`, а не из пользовательского ввода.
- Любой запрос к задаче должен быть ограничен Telegram ID текущего пользователя.
- Храни время в SQLite в нормализованном UTC-представлении с timezone-aware datetime в приложении.
- Показывай пользователю время в `Asia/Almaty`; день для `/today` определяй по этой временной зоне.
- Не используй naive datetime и не сравнивай даты в разных временных зонах без нормализации.
- Дедлайн должен быть в будущем на момент сохранения.
- Статусы MVP: `pending` и `completed`.
- Не записывай токен бота, содержимое `.env` или секреты в логи, репозиторий и тестовые фикстуры.

## 5. Качество кода

- Используй type hints для публичных функций и основных структур данных.
- Предпочитай короткие функции с одной ответственностью.
- Обрабатывай ожидаемые ошибки ввода понятным русскоязычным сообщением; неожиданные ошибки логируй без секретов и не отправляй пользователю stack trace.
- SQL выполняй через параметры, не собирай запросы конкатенацией пользовательского ввода.
- Закрывай подключения и фоновые задачи при корректном завершении приложения.
- Не подавляй ошибки пустым `except`; перехватывай конкретные исключения.
- Не добавляй абстракции, которые не нужны текущему MVP.

## 6. Тестирование

Минимально тестируй:

- валидацию названия и формата дедлайна;
- запрет дедлайна в прошлом;
- работу с задачами разных пользователей;
- выборку задач на локальный день в `Asia/Almaty`;
- переход `pending` → `completed`;
- отправку только одного напоминания;
- поведение напоминаний после перезапуска и для уже просроченных задач.

Для тестов используй временную SQLite БД и подменяемые Telegram API/часы, если это необходимо. Тесты не должны обращаться к реальному Telegram API.

## 7. Git и коммиты

- Каждая работа должна ссылаться на GitHub Issue.
- Один PR — одна логическая задача; не смешивай рефакторинг с независимой функциональностью.
- Имена веток: `feat/<issue-number>-short-name`, `fix/<issue-number>-short-name`, `chore/<issue-number>-short-name`.
- Формат коммитов: Conventional Commits, например `feat(tasks): add task creation flow` или `test(reminders): cover restart recovery`.
- Не коммить `.env`, локальную БД, виртуальное окружение, токены или кэш.
- В PR укажи Issue, краткое решение, проверку/тесты и ограничения.

## 8. Запрещённый scope creep

Без отдельного одобренного Issue не добавляй LLM, платные API, веб-интерфейс, Google Calendar, авторизацию вне Telegram, групповые чаты, аналитику, платежи, рассылки и многопользовательские курсы.

## 9. Definition of Done

Задача завершена, когда её Acceptance Criteria выполнены, тесты проходят, README/спецификация обновлены при необходимости, секреты не добавлены, а изменения готовы к ревью в отдельном PR.
