# [Chore] Bootstrap UniMate project and runtime

**Labels:** `chore`, `setup`  
**Dependencies:** none

## Context

Нужен минимальный воспроизводимый Python-проект для UniMate. Базовый запуск, конфигурация, логирование и тестовая инфраструктура должны быть подготовлены до реализации продуктовых функций. Не добавляйте функции сверх `spec.md`.

## Requirements

- Создать проект на Python 3.12+ с aiogram 3.x.
- Создать модульную структуру приложения, соответствующую `AGENT.md` и `spec.md`.
- Загружать конфигурацию из переменных окружения; `BOT_TOKEN` обязателен.
- Добавить `.env.example` с фиктивным значением токена и `.gitignore` для `.env`, SQLite-файлов, `.venv`, кешей и тестовых артефактов.
- Добавить `requirements.txt` с выбранными совместимыми версиями библиотек.
- Настроить базовое логирование и корректное завершение polling/фоновых задач при остановке.
- Реализовать стартовый handler `/start` с коротким русскоязычным приветствием. На этом этапе достаточно базового ответа без полноценного управления задачами.
- Добавить pytest и базовый тест конфигурации/запуска без обращения к реальному Telegram API.
- Обновить README инструкциями создания окружения, установки зависимостей, настройки `.env` и локального запуска.

## Technical Implementation Steps

1. Создать `app/main.py` и `app/config.py`; не размещать всю логику в одном файле.
2. Сделать конфигурацию валидируемой: при отсутствии `BOT_TOKEN` завершать запуск с понятным сообщением.
3. Создать router для `/start` и подключить его к Dispatcher.
4. Настроить `pytest` и изолировать тесты от реального Telegram API.
5. Проверить, что локальные секреты и база данных исключены из git.
6. Документировать точные команды запуска и тестирования.

## Acceptance Criteria

- [ ] `python -m app.main` стартует при корректном `BOT_TOKEN` и пытается подключиться к Telegram.
- [ ] Без `BOT_TOKEN` запуск завершается с понятной ошибкой, не печатая секреты.
- [ ] В личном чате `/start` отвечает на русском языке.
- [ ] Проект имеет отдельные модули конфигурации и обработчиков; код не свален целиком в один файл.
- [ ] `pytest` запускается локально и проходит без токена и без сети.
- [ ] `.env`, SQLite-файлы, `.venv` и Python-кеши перечислены в `.gitignore`.
- [ ] README содержит команды для установки, запуска и тестов.
- [ ] В репозитории нет настоящего токена или иных секретов.

# [Feature] Add persistent SQLite task repository

**Labels:** `feature`, `database`  
**Dependencies:** Issue 1

## Context

Задачи должны сохраняться между перезапусками бота. До подключения Telegram-сценариев нужен проверяемый слой хранения, который соблюдает изоляцию данных по Telegram ID и правила времени из `spec.md`.

## Requirements

- Использовать SQLite через `aiosqlite`.
- Реализовать таблицу `tasks` согласно разделу 10 `spec.md`.
- Хранить временные значения в UTC ISO-8601 и использовать timezone-aware datetime на уровне Python.
- Реализовать repository-операции: создание задачи, получение активных задач пользователя, получение задач пользователя на интервал времени, поиск задачи по ID вместе с владельцем, отметка задачи завершённой и выборка задач для отправки напоминаний.
- Каждый пользовательский запрос должен ограничиваться `telegram_user_id`.
- SQL-запросы должны быть параметризованными.
- Инициализация БД должна быть идемпотентной: повторный запуск не уничтожает сохранённые задачи.
- Для тестов должна поддерживаться отдельная временная БД.

## Technical Implementation Steps

1. Добавить слой соединения и schema initialization.
2. Создать repository с асинхронными методами и чётко описанными типами входа/выхода.
3. Добавить индекс по `(telegram_user_id, status, deadline_at)`.
4. Определить единый способ сериализации/deserialization UTC datetime; не использовать naive datetime.
5. Написать тесты на создание, выборку, завершение, сохранение после повторной инициализации и изоляцию двух пользователей.
6. Не добавлять ORM или миграционный инструмент без необходимости для этого SQLite MVP.

## Acceptance Criteria

- [ ] Таблица и индекс создаются автоматически при старте, если их ещё нет.
- [ ] Повторная инициализация не удаляет уже сохранённые задачи.
- [ ] Repository создаёт и возвращает задачу с корректно сохранённым UTC-дедлайном.
- [ ] Запрос активных задач возвращает только задачи переданного Telegram ID, в порядке дедлайна.
- [ ] Невозможно получить или завершить чужую задачу, передав её ID без совпадения владельца.
- [ ] Отметка завершения сохраняет статус `completed` и `completed_at`.
- [ ] Тесты выполняются на временной SQLite БД и не используют реальные пользовательские данные.
- [ ] Ошибочные пользовательские значения не интерполируются напрямую в SQL.

# [Feature] Implement task creation conversation

**Labels:** `feature`, `telegram`  
**Dependencies:** Issues 1–2

## Context

Основная ценность UniMate — дать студенту возможность быстро записать учебную задачу с конкретным дедлайном. Создание должно быть предсказуемым и не требовать AI или свободного разбора естественного языка.

## Requirements

- `/add` и кнопка «Добавить задачу» запускают один и тот же сценарий.
- Бот последовательно запрашивает название, а затем дедлайн.
- Название после удаления пробелов по краям должно содержать от 1 до 200 символов.
- Формат дедлайна: `ДД.ММ.ГГГГ ЧЧ:ММ`; время интерпретируется в `Asia/Almaty`.
- Дедлайн должен быть строго в будущем относительно момента сохранения.
- При некорректном вводе бот объясняет ошибку и повторно запрашивает соответствующее поле; задача не сохраняется до успешной валидации обоих полей.
- `/cancel` отменяет процесс на любом шаге и очищает временное состояние.
- После успешного сохранения бот подтверждает название, локальный дедлайн и то, что напоминание планируется за час до дедлайна.
- Создание задачи доступно только в личном чате.

## Technical Implementation Steps

1. Реализовать FSM для шагов `waiting_for_title` и `waiting_for_deadline`.
2. Вынести парсинг/валидацию названия и дедлайна в тестируемые функции сервиса.
3. Преобразовывать введённое местное время в UTC перед сохранением.
4. Сохранение выполнять через repository из Issue 2, не писать SQL внутри handler.
5. Добавить `/cancel` и защиту от старого/неполного состояния.
6. Написать тесты на граничные случаи; если тестируется FSM handler, подменять Telegram API.

## Acceptance Criteria

- [ ] `/add` и кнопка «Добавить задачу» запускают одинаковый сценарий.
- [ ] Валидные название и будущий дедлайн создают ровно одну задачу текущего пользователя.
- [ ] Пустое название, название длиннее 200 символов, неверный формат даты и прошедший дедлайн отклоняются с понятным сообщением.
- [ ] После ошибочного дедлайна пользователь может ввести его заново без повторного ввода названия.
- [ ] `/cancel` на любом шаге очищает состояние и не сохраняет задачу.
- [ ] Подтверждение показывает дедлайн в `Asia/Almaty`.
- [ ] Время, сохранённое в БД, представляет тот же момент времени в UTC.
- [ ] Сценарий не работает как создание задачи в групповых чатах.

# [Feature] Add task lists, today view and completion action

**Labels:** `feature`, `telegram`  
**Dependencies:** Issues 1–3

## Context

После создания задачи пользователю нужно быстро находить ближайшие дедлайны и исключать выполненные задания из активного списка. Списки должны показывать только принадлежащие пользователю задачи.

## Requirements

- `/tasks` и кнопка «Мои задачи» показывают все активные задачи пользователя, отсортированные от ближайшего дедлайна к дальнему.
- На одной странице отображается не больше 10 задач; если задач больше, доступны кнопки «Назад» и «Далее».
- В карточке задачи показываются название, дедлайн в `Asia/Almaty` и кнопка «Выполнено».
- `/today` и кнопка «На сегодня» показывают только активные задачи, дедлайн которых попадает в текущий календарный день в `Asia/Almaty`.
- При пустом списке бот сообщает об этом и предлагает добавить задачу.
- Нажатие «Выполнено» переводит принадлежащую пользователю активную задачу в `completed`.
- Повторное нажатие на кнопку завершения безопасно и не вызывает исключения.
- Callback должен проверять владельца задачи; нельзя полагаться на то, что пользователь не изменит callback data.
- Завершённая задача не появляется в активных списках и не должна получить напоминание.

## Technical Implementation Steps

1. Реализовать handler для `/tasks`, `/today` и соответствующих кнопок.
2. Добавить пагинацию списка активных задач по 10 элементов.
3. Создать callback-data для действия завершения; перед обновлением повторно проверить владельца и статус в repository.
4. Рассчитывать границы сегодняшнего дня в `Asia/Almaty`, затем передавать в repository соответствующий UTC-интервал `[start, next_start)`.
5. Обновить клавиатуру и/или сообщение после завершения задачи.
6. Добавить тесты на порядок, пагинацию, границы локального дня, повторное завершение и изоляцию пользователей.

## Acceptance Criteria

- [ ] `/tasks` показывает только `pending`-задачи текущего пользователя в порядке возрастания дедлайна.
- [ ] Пагинация отображает не более 10 задач на странице и корректно обрабатывает первую/последнюю страницу.
- [ ] `/today` учитывает местную дату `Asia/Almaty`, включая задачу в 00:00 и исключая задачу ровно в 00:00 следующего дня.
- [ ] Кнопка «Выполнено» обновляет только задачу владельца callback.
- [ ] Чужая, уже завершённая или несуществующая задача не вызывает непредусмотренного изменения; пользователь получает нейтральный ответ.
- [ ] После завершения задача исчезает из активных списков.
- [ ] Пустое состояние обработано понятным русскоязычным сообщением.
- [ ] Тесты проверяют доступ между двумя разными Telegram ID.

# [Feature] Implement persistent deadline reminder worker

**Labels:** `feature`, `reminders`  
**Dependencies:** Issues 1–4

## Context

Ключевая ценность UniMate — напомнить о дедлайне до его наступления. Напоминания нельзя держать только в оперативной памяти: после перезапуска приложения состояние должно восстанавливаться из SQLite.

## Requirements

- Для задачи время напоминания равно `deadline_at - 1 hour`.
- Запускать asyncio worker, который проверяет ожидающие напоминания каждые 30 секунд.
- Для отправки подходят только задачи со статусом `pending`, без `reminder_sent_at`, с дедлайном в будущем и наступившим временем напоминания.
- После успешной отправки через Telegram API сохранять `reminder_sent_at`.
- Если до дедлайна при создании осталось меньше часа, worker отправляет напоминание при ближайшей проверке.
- При перезапуске worker подбирает задачи, для которых время напоминания уже наступило, но дедлайн ещё впереди.
- Просроченные и завершённые задачи не получают напоминаний.
- Ошибка отправки одной задачи логируется и не завершает worker; неуспешная отправка не должна отмечаться как успешная.
- Напоминание включает название задачи, локальный дедлайн и короткий призыв проверить задание.
- Worker и его ресурсы должны корректно останавливаться при выключении приложения.

## Technical Implementation Steps

1. Добавить repository-метод для выборки кандидатов на напоминание.
2. Реализовать `reminder_service` с периодическим циклом и явным интервалом 30 секунд.
3. Отправлять сообщения через объект Bot; не создавать новые экземпляры Bot на каждую задачу.
4. После успешного ответа Telegram API сохранять timestamp отправки.
5. Для исключений на уровне одной задачи логировать безопасный контекст и продолжать цикл.
6. Добавить тесты с подменённым Bot API и фиксируемым временем: до времени напоминания, наступившее время, уже завершённая задача, просроченный дедлайн, повторная проверка, перезапуск, ошибка Telegram API.
7. Обновить README: напоминания работают только пока процесс запущен.

## Acceptance Criteria

- [ ] Активная задача с дедлайном более чем через час получает напоминание не раньше `deadline - 1 hour` и при работающем боте — в пределах одного интервала проверки после наступления времени напоминания.
- [ ] Для задачи, созданной менее чем за час до дедлайна, напоминание отправляется при ближайшем цикле worker, если дедлайн всё ещё впереди.
- [ ] Одна задача не получает одно и то же успешно отправленное напоминание повторно после следующей проверки или перезапуска.
- [ ] При выключенном боте и последующем запуске worker отправляет пропущенное напоминание только если дедлайн ещё не наступил.
- [ ] Выполненные и просроченные задачи пропускаются.
- [ ] При исключении Telegram API worker продолжает обрабатывать другие задачи и не записывает неуспешную отправку как успешную.
- [ ] Все тесты напоминаний работают без реального токена и сети.
- [ ] README предупреждает, что процесс должен работать постоянно для своевременных напоминаний.
